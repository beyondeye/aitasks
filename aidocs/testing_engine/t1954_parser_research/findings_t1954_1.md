# Findings — t1954_1 (corpus, oracle, harness, baseline)

- Date: 2026-10-12.
- Baseline: `annot` at `f096db065a72` (goengines tree `200bd2130a1d`), via
  `baseline/PIN`.
- Environment: `results/environment.md`.
- Every number below comes from a committed result file. Each is named, and
  each can be rerun with the commands in `README.md`.

This file keeps four kinds of statement apart:
- **observations**: measured here;
- **documentation claims**: what upstream says, not verified here;
- **assumptions**: taken without proof;
- **unknowns**.

## Observations

### Infrastructure

1. **The evaluation seam is behaviour-neutral.** The baseline matrix built
   against the unpatched snapshot and against the patched-but-unhooked one
   is byte-identical (28,593 bytes, identity line aside) —
   `results/guard.md`. Negative control: a mutant unpatched snapshot (Go
   package anchor dropped) makes the guard fail. So the guard can see a
   difference.
2. **The baseline is immutable and checked on every run.** Every verb exits
   2 on any of these (verified by hand, 2026-10-12):
   - a tampered `IDENTITY` commit, tree or seam sha;
   - a missing `IDENTITY`;
   - a missing snapshot;
   - an edited snapshot file, caught by the new `content_sha256` over every
     file.

   `fetch.sh` refuses a PIN whose tree id or seam sha256 does not match,
   also with exit 2. The binary's build info must show `goengines` replaced
   by the snapshot directory.
3. **Capability contract (plan amendment A2).** `ToContext` enforces each
   operation's needs itself. Without placement anchors, only the fresh
   file-level insertion is `unsupported`; a restamp, a member insertion and
   a file-level append by the same provider are applied through the real
   `PlanCovers → Apply`. Declared-zero anchors are accepted; `Errors=false`
   blocks every write while classes still score; Python without
   `DocLiterals` loses records and writes but keeps classes. Raw (direct)
   writes get the same check. A provider failure during an edit is reported
   "not measured", never as a refusal or as corruption. Pinned by
   `provider/adapter_test.go` (5 tests) and `internal/runner/caps_test.go`
   (6 tests through the seam).
4. **The accounting cannot hide a gap** (`internal/runner/review_test.go`
   and the other regression tests):
   - file-mode fidelity compares the mode before the operation with the mode
     after it (a 0755 → 0600 write is reported);
   - a behaviour check whose run cannot happen (missing tool, launch
     failure) or that is switched off (`--behaviour=false`) is counted "not
     measured", never "unchanged";
   - if the subject fails when the records are read back after a
     successful write, the write stands but its records are "not verified",
     never compared as an empty list and scored as corruption;
   - full-cover evidence must be an exact, contiguous partition of the
     input (duplicate leaves that rebuild the bytes do not pass);
   - the native composite refuses to run with a part missing, and bench
     rows name the composition actually built;
   - the TypeScript oracle receives the real file name, because the script
     kind changes the parse (`<number>1` in `.ts`);
   - benchmark peak RSS is the maximum over all samples.

### Corpus and native cross-checks — `results/oracle_check.md`

5. **The corpus has 213 fixtures:**

   | lang | fixtures |

   | Python | 61 |
   | Go | 20 |
   | Kotlin | 25 |
   | TS/JS | 12 |
   | Java | 10 |
   | Rust | 9 |
   | Swift | 10 |

   - 114 are the landed M2.2 fixtures and test tables, imported from the
     pinned commit (regenerated byte-identical to the landed `.in` files).
     Their `.expect` comes from the M2.2 goldens and hand-written class
     strings.
   - The rest are hand oracles.
   - Every ordinary, difficult, malformed, embedded-language and
     unsupported-construct class is present in every language, and so is
     the mandatory edit set.
6. **Native tools agree with every hand expectation they can check (0
   unexplained disagreements):**

   | tool | languages | evidence |
   |---|---|---|
   | `bash -n` + execution | bash | validity |
   | Python `tokenize`/`ast` | Python | validity, comments |
   | `go/parser` + `go/scanner` | Go | validity, comments |
   | kotlinc 2.4.21 (scratch download, JDK 21) | Kotlin | validity |
   | TypeScript 5.9.3 parser | TS/JS | validity, comments |
   | javac 21 | Java | validity |
   | rustc 1.98.1 `--edition 2021` | Rust | validity |
   | swiftc 6.2.4 (docker) | Swift | validity |

   All 34 `exec:` fixtures ran. The Kotlin and Swift compilers were
   obtained, so no language's native evidence is `none`.
7. **A context-free scanner is not an oracle (plan amendment A1),
   reproduced.** A bare `ts.createScanner` loop:
   - reports the fake `// testmap:covers` inside a template continuation
     after `${x}`;
   - misses the real comment after it;
   - also fails nested templates, a regex literal containing `/*`, and JSX
     text.

   The parser-aware extractor passes all 7 pinned self-test cases, and the
   naive loop is the negative control (`oracle/ts_oracle.js --selftest`).
8. **Where the landed M2.2 expectation was a fail-closed choice rather than
   ground truth, the native tool decided (bash 5.3.15 execution):**
   - `$'E\x4fF'` as a heredoc delimiter is decoded to `EOF`, making line 3
     of `lex_heredoc_escape_in_quoted_delimiter` a **real annotation**;
   - `$(( cd a\n) )` is a valid subshell.

   Both are now `expect: certain`; M2.2's refusals of them are measured as
   over-refusal. Two other M2.2 classifications are kept as **policy**: a
   real comment inside a backtick substitution, and a comment on a
   backslash-continuation line. Both are real comments that M2.2 by design
   never treats as annotation lines (`x-policy`). A subject classing them
   Comment is reported as a policy divergence, not FP-writable.

### Baseline (landed M2.2) — `results/matrix_baseline.md`

9. **Safety columns are 0 in bash, Go and Kotlin (111 fixtures).** Python
   has **one defect: the UTF-8 BOM** (`python/bom_doc.py`, 3
   record-corruption counts, 1 fidelity, 2 behaviour):
   - The baseline does not see a module docstring after a UTF-8 BOM, so it
     misses its `testmap:` record. CPython's `ast.get_docstring` sees it.
   - A fresh file-level insertion then goes to line 0, **above the BOM**.
     That moves the BOM mid-file, and the module stops running: exit 0 → 1,
     `SyntaxError: invalid non-printable character U+FEFF`, reproduced by
     hand.
   - `Apply`'s own checks pass, because every other line keeps its bytes
     and class.
   - Exposure today is nil: none of the 5,723 source files in the six
     surveyed repositories starts with a BOM.
   - Bash with a BOM is correctly not special: bash gives the BOM no
     meaning.
10. **Over-refusal (cost, fail-closed) in bash: 3 valid files refused:**
   - `$((`-ambiguous subshell;
   - an ANSI-C heredoc delimiter;
   - a multi-line heredoc inside backticks that bash accepts.

   **Read-mismatch: 2 in bash** (the refused files) and 1 in Python (the
   BOM case). **Recall:** 0 missed writable lines and 0 missed comment lines
   in all four languages.
11. **The four research languages are `unsupported` for the baseline (41
    fixtures).** The landed `fixedPosition` has no rule for them: it falls
    to bash-like "after the leading comment block". The corpus records the
    *proposed* rules instead (TS/JS after imports + prologue; Java after
    imports, else package; Rust after inner attributes + `use`; Swift after
    imports). These are research proposals, not validated behaviour.

### Native providers through the seam — `results/matrix_*.md`

12. **`goscanner` (go/scanner, Go): 0 on every metric.** 20/20 range checks
    pass, and it agrees with the baseline on all 249 Go files of the six
    repositories.
13. **`pytokenize` (Python tokenize + ast, Python): 0 on every safety
    metric**, and 61/61 range checks pass.
    - It has 2 over-refusals: the lexically valid files whose grammar is
      invalid, which it refuses because `ast` fails. That is a cost by
      construction.
    - It agrees with the baseline on all 1,828 Python files of the six
      repositories.
    - So the landed Python lexer matched CPython's tokenizer everywhere
      measured, except the BOM case (observation 9).
14. **`shfmt` (mvdan.cc/sh/v3 v3.14.1, bash): 2 FP-writable and 1
    silent-uncertain, both safety failures**, plus 8 over-refusals and 6
    read-mismatches:
    - **FP-writable:** in an unquoted `<<-` heredoc, mvdan matches the
      delimiter before joining a backslash-newline, so it reads heredoc
      **data** as a comment annotation (`lex_heredoc_strip_continuation`).
      Bash execution confirms the hand oracle.
    - **Silent-uncertain:** it does not flag the unterminated heredoc inside
      a backtick substitution (`lex_heredoc_in_backticks`).
    - **Over-refusals:** `$((`-ambiguous subshells, Latin-1 bytes ("invalid
      UTF-8"), an ANSI-C heredoc delimiter, and a grammar error that does
      not affect comment context.
    - **On real repositories:** it refuses 10 of 1,620 bash files the
      baseline reads, and differs on 1 comment line. That line is a comment
      after a `; \` continuation, the policy case (observation 8).
    - Evidence for t1954_3.

## Documentation claims (not verified here)

- gotreesitter's README: 206 grammars, 119 with hand-written Go external
  scanners, "all producing error-free trees on smoke samples". Only the 9
  research grammars were exercised, on one snippet each.
- malivvan/tree-sitter's README: "pre release software".
- Swift's bare `/…/` regex literals need Swift 6 mode or
  `-enable-bare-slash-regex`. The native check passes the flag; observed
  only as the parse error without it.
- TypeScript's parser does not implement Annex B HTML-like comments. This
  is observed (the parser rejects `html_comments.js`, which node runs); the
  reason is assumed.

## Assumptions

- The hand oracles encode one policy: annotations live only on comment lines
  that start at a line's first non-blank byte with the literal leader bytes,
  outside every string, heredoc, block comment, backtick substitution and
  continuation line. A line whose leader is written as Java unicode escapes
  is therefore never an annotation. This is the M2.2 contract (Invariant 6)
  extended to the research languages; nobody has validated it for TS/JS,
  Java, Rust or Swift as a product decision.
- A malformed file is one its native tool rejects, or one bash accepts only
  with a "here-document delimited by end-of-file" warning. Lexically valid
  files with grammar errors are `certain`.
- The proposed file-level placement rules for TS/JS, Java, Rust and Swift
  (observation 11).
- The M2.2 bench shape stands for real repositories' scan cost. The
  real-repository walks measure disagreement, not time.

## Unknowns

- Kotlin, Java, Rust and Swift have no comment-range oracle here, only
  validity and execution evidence (kotlinc / javac / rustc / swiftc). Their
  comment-line expectations rest on the hand oracle, cross-checked only for
  well-formedness.
- How the candidates of t1954_2/3 score is open: they plug into this
  harness.
- The `aitasks` real-repository walk read the working tree of a shared
  checkout, including other sessions' uncommitted edits. It is
  moment-relative. HEAD at measurement is in `results/environment.md`.
