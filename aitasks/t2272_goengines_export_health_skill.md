## Goal

Add a skill to this (public) repository for the receiving side of the one-way `goengines/` export from aitasks_go. It should:

- verify that the exported tree is healthy;
- answer whether a given aitasks_go task's code is already exported;
- guide the review and the path-scoped commit of a staged export.

The private-side counterpart, which curates the `export` branch and runs `promote/export.sh`, is aitasks_go#t118. This task holds on it through `xdeps`, so the two skills can share one line protocol and vocabulary.

## Context (as of 2026-11-10)

- `goengines/` here is **generated**. Every `.go` file carries `// Code generated by aitasks_go export from <sha>; DO NOT EDIT.` `goengines/EXPORT.txt` records:
  - the source sha (`source: beyondeye/aitasks_go@544ed20…` today);
  - the manifest digest and the private gate results;
  - a sorted file list with per-file sha256, and the removals.
- Only `goengines/README.md` and `.gitignore` are public-maintained.
- Each export is one commit here with the trailer `Exported-From: beyondeye/aitasks_go@<sha>`; the bootstrap is 6405506d1. The exporter **stages but never commits**: the operator commits path-scoped (`git commit -F <msg> -- goengines`).
- An emergency public fix needs a `Return-To: aitasks_go` trailer plus a return task there. aitasks_go's `export.sh --pull-back --from <this checkout>` turns public edits into a patch, and any unreturned edit makes the next export refuse with `REFUSED:drift`.
- Policy: aitasks_go `aidocs/aitasks_go/ship_path.md`. Operator reference: aitasks_go `promote/README.md`.

## Scope (the skill's steps)

1. **Health of the current tree** (read-only):
   - every file listed in `EXPORT.txt` exists with the recorded sha256;
   - every `.go` file under `goengines/` (except public-maintained paths) carries the header naming the recorded sha, and no unlisted file exists;
   - an independent build (`GOWORK=off`, public proxy, `go mod tidy -diff` clean, `go build ./...`, `go vet ./...`, `build.sh host`);
   - `ait-testmap version` matches `VERSION`, and the shim resolves it (`aitask_testmap.sh` handshake).
   Report drift (hand edits since the export) and point at the return path (`Return-To:` trailer, return task in aitasks_go, `--pull-back`).
2. **"Is aitasks_go#tN exported?"**
   - Resolve the task's code commits in aitasks_go: the `(tN)` commit suffix, through the registered sibling project.
   - Answer exported / not exported / partially exported, checking with `git merge-base --is-ancestor <commit> <EXPORT.txt source>` in the aitasks_go checkout.
   - List which shipped commands the task's files reach.
   - Without access to the private repository, say "unknown", never "not exported".
3. **Reviewing a staged export:** summarise the staged `goengines/` diff per command and flag:
   - contract or interface changes: the `version` output, the verb table, exit codes, `testmap.Contract`;
   - new generated registry files with rollout implications. For example, t62's `aitestmap/registry/_runners.yaml` makes engines older than aitasks_go 32ddfe1 refuse the registry, so every host must upgrade before anyone rescans.

   Then print the path-scoped commit command with the exporter's message. Never commit or push without explicit approval.
