# Plan — t1159: Shadow review-loop automation

## Context

The plan-review / impl-review feedback cycle between the shadow agent and the followed (main) agent is fully manual today: the user watches for the followed agent to finish addressing concerns, focuses the shadow pane, and types "refetch and recheck" by hand; the concern block carries no round number or review time, so a repeat round with identical concerns is silently dedup-suppressed by minimonitor's auto-offer; and secondary concerns either bloat the plan or get lost. This task automates the **critical seam — followed agent → shadow auto-recheck** (per the 2026-08-05 scope-priority clarification), adds **round metadata** to the concern block (also the freshness key-space t1448 is chartered to consume), and adds a **per-concern spin-off-as-task triage arm** (folded t1017 steerability requirement). All predecessors have landed (t1294, t1289, t1319, t1293, t1427+children, t1420, t1474 — trail `art:trail-shadow-review-loop` confirms t1159 is next and unblocked).

## Pinned decisions (user-confirmed 2026-08-11)

1. **Architecture: minimonitor-orchestrated loop.** Arm/disarm keybinding + pure state machine serviced from minimonitor's refresh tick; when the followed agent settles at a prompt after the shadow's last read, minimonitor sends a single-line "refetch and recheck" into the **shadow** pane. The advisory-only guardrail binds the shadow, not minimonitor — the followed pane is never written.
2. **Forwarding stays clipboard-only.** No injection into the followed pane this task.
3. **Triage spin-off arm creates tasks directly:** fourth per-row picker state; on confirm, shell out to `aitask_create.sh --batch --silent --desc-file -` per spun-off concern (draft creation, no `--commit`).
4. **Rejection suppression stays task-scoped** (no round field in the t1427 store; `shadow_agent.md` records that rationale). Round metadata's roles: display, lifting the auto-offer dedup on repeat rounds, t1448's freshness key.
5. **Decomposition: 4 children** (confirmed), plus the aggregate manual-verification sibling offer after child plans are written.

## Design summary

### Round metadata (t1159_1)

- **Grammar:** one non-marker header line immediately after the opening fence, before the first item: `Round: <N> @ <ISO-8601-UTC-with-seconds>Z` (e.g. `Round: 2 @ 2026-08-11T14:03:27Z`). **Seconds resolution is required** — a same-minute shadow restart would otherwise reproduce the same `(round, reviewed_at)` pair and defeat both the dedup lift and t1448's freshness key. Parser-safe by construction: `_scan_items` (`concern_parser.py:352`) drops a non-marker line before the first item (`items` empty ⇒ no continuation join), so `parse_concerns` / `has_concern_block` / `unrecovered_markers` are unaffected. It deliberately changes `concern_block_signature` (round bump re-hashes the monitor's freshness badge). Placement hazard (after an item ⇒ body-joined) is documented and test-pinned. **Never widen the `[priority | region]` bracket** (t1167 hazard).
- **Round counter: mechanically anchored, shadow-executed.** The recheck prompt minimonitor composes **names the expected round** (`recheck round <N+1>`), derived by `parse_block_meta` from the shadow's previous block — so after the first block, the round number is machine-derived, not LLM-counted. Producers honor an externally supplied round when the request names one, and fall back to self-counting only for the first review / manual free-text rechecks. Producers source the timestamp mechanically (`date -u +%Y-%m-%dT%H:%M:%SZ` — the shadow has shell access) rather than estimating it. Restart ⇒ round 1 again; consumers key on the `(round, reviewed_at)` pair. No new state store.
- **New parser accessor** in `concern_parser.py`: `BlockMeta(round: int, reviewed_at: str)` + `parse_block_meta(text) -> BlockMeta | None`, using `_last_block_region(text, require_close=False)` (same forgiving region as `parse_concerns`); only the first non-blank line of the region is consulted; `reviewed_at` verbatim, fail-open. Docstring carries the t1448 consumer contract (freshness key = the pair).
- **Producers:** all 4 files (`plan-challenge.md`, `impl-challenge.md`, `plan-assumptions.md`, `plan-diagnose-errors.md`), both rule sites each (emit paragraph + rules-list bullet), plus `Round: 1 @ …` prepended to each example block (examples never gain fences — t1123 guard). Producers are plain shared `.md` — **no goldens regeneration needed**; do not touch `SKILL.md.j2`.
- **Clean reviews emit a metadata-only block** (closes the clean-round counting gap): when a review finds zero concerns (or suppression removes them all), the producer still emits the fences with **only** the round header between them — a machine-readable round-completion record. Parser consequences (all verified against the entry points): `has_concern_block` stays False (no items ⇒ no auto-offer — correct, nothing to pick); `parse_concerns` returns `[]`; `parse_block_meta` reads the round — so the next round's derivation never repeats a clean round's number, and t1448's freshness key advances on clean rounds too. Documented in `concern-format.md`'s round-header section; producer wording covers the zero-concern case explicitly at both rule sites.
- **Dedup lift** (`minimonitor_app.py:2352-2355`): dedup key becomes `f"round={meta.round}@{meta.reviewed_at}\n{payload}"` when meta present, bare payload otherwise (byte-identical back-compat). Toast gains `(round N)`; picker gets optional `block_meta` display.
- **`concern-format.md`:** new "Round header" section (grammar, placement hazard, back-compat, three consumer roles, signature note).

### Auto-recheck loop (t1159_2, depends: _1)

- **New pure module `.aitask-scripts/monitor/review_loop.py`** (no tmux/Textual/I-O): `ReviewLoopController` with states DISARMED/WAITING/FIRED, `tick(agent_present, shadow_present, awaiting_input, stale, shadow_ready, modal_open, now) -> 'none'|'fire'|'auto_disarm'`. **Edge-driven by design:** a fired recheck makes the shadow re-capture, which restamps `@aitask_shadow_analyzed_at` and clears the very staleness that fired it — so after a fire, stay FIRED until `stale is False` is positively observed, then re-arm. Debounce `DEBOUNCE_TICKS = 3` consecutive ticks of (`awaiting_input is True` AND `stale is True`), any negative/None resets (t1446 AUTO_CLOSE pattern); cooldown `COOLDOWN_SECONDS = 45`; `None` staleness never advances nor clears (tri-state discipline).
- **Shadow-readiness condition (hard, not a stretch):** the controller never fires while the shadow is busy. `shadow_ready` is a tri-state input; the fire condition requires `shadow_ready is True` **in addition to** the debounced trigger — a satisfied trigger with a busy/indeterminate shadow **holds** (streak preserved, banner shows "waiting for shadow to settle") and fires on the first ready tick; it never drops the episode. **Readiness is positive prompt detection, not mere inactivity** (hash stability alone would pass a shadow parked at an AskUserQuestion, a tool-approval dialog, or holding half-typed composer text). New pure function `shadow_prompt_ready(text) -> bool | None` in `review_loop.py`, evaluated on the shadow capture minimonitor already performs each tick (no new tmux traffic), requiring **all three**: (a) positive — the tail shows the shadow agent's **empty** input composer (a composer prompt line with no typed text; exact pattern pinned from real-widget fixtures, see pre-phase); (b) negative — no dialog/prompt pattern for that agent (`prompt_patterns` list) matches the tail (a dialog is a different interaction; Enter there answers it); (c) capture hash unchanged for ≥2 consecutive ticks (cheap conjunct against streaming). Any condition unknown/failed capture ⇒ not-ready. The composer pattern is version-sensitive by nature — maintained in-place like `prompt_patterns.py` (t1474 practice) and pinned against captured fixtures of shadow-at-rest / shadow-streaming / shadow-at-dialog / shadow-with-typed-text.
- **Shadow-agent dispatch (the shadow's agent is independently selectable):** the shadow is launched via the `shadow` codeagent op and `E` lets the user pick any configured agent, so a Claude followed pane can have a Codex/OpenCode shadow — and a Claude-only composer pattern would hold forever. Readiness detection is a per-agent dispatch table `SHADOW_READY_DETECTORS: dict[agent, detector]` in `review_loop.py` (initially populated for `claude` only). At arm time, resolve the **shadow pane's** actual agent (its `current_command` → `agent_key_from_command`) and check **both** capabilities: the followed agent's `live_tiers_available` (trigger side) AND the shadow agent's presence in `SHADOW_READY_DETECTORS` (delivery side) — refuse visibly on either gap ("auto-recheck unavailable: shadow agent '<a>' has no readiness detection yet"). The per-tick service re-resolves the shadow agent and auto-disarms (visibly) if the shadow is replaced with an unsupported agent mid-loop.
- `compose_recheck_prompt(phase, expected_round) -> str`: phase pre-selects wording (PLAN → plan-challenge wording; IMPLEMENT/POSTIMPL → impl-challenge wording), **total over all inputs** — None/UNKNOWN/garbage get generic wording; phase may pick wording, never refuse (advisory-only; negative control required). `expected_round` (from `parse_block_meta(previous shadow capture).round + 1`, or `None` before any block) is woven into the text as `recheck round <N>` so the round number is mechanically anchored.
- **Minimonitor wiring:** `Binding("L", "toggle_review_loop", ...)` (free key); `action_toggle_review_loop` with per-action refusals (no agent; no shadow → suggest `e`; `live_tiers_available(followed_agent)` False → visible "no prompt detection yet (t1467)" warning; shadow agent not in `SHADOW_READY_DETECTORS` → visible refusal — both are **agent-capability gates, not phase gates**); `_service_review_loop(snap, shadow_pane)` called from all three branches of `_maybe_offer_concerns` (agent-gone, shadow-gone, main path after `_restamp_shadow_phase` at line 2323) using the cached tri-state `_shadow_feedback_stale` — no new tmux traffic; `_fire_shadow_recheck` sends `send_keys(shadow_pane, prompt, literal=True)` + `send_keys(shadow_pane, "Enter")` (`monitor_core.py:2458-2472`, `--` separator seam). Banner `#mini-loop-status` (copy `_set_shadow_stale_banner` pattern, `_loop_banner_text` test seam); key-hints line `L:auto-recheck loop`.
- **Safety contract** (reproduced in `shadow_agent.md`): (1) followed pane never written — `_fire_shadow_recheck` receives no followed pane id; unit test asserts no send names it; (2) opt-in + permanently visible banner; (3) edge-driven once per episode + cooldown; (4) positive-evidence debounce; (5) **never inject into a busy shadow** — fire requires `shadow_ready is True`, which is the three-part positive readiness check (agent-specific **empty-composer** detection AND **no dialog/prompt pattern** matching the tail AND capture-hash stability ≥2 ticks — hash stability alone is never sufficient), holds otherwise; (6) auto-disarm on shadow/agent disappearance (visible), pause on modal; (7) single-line literal injection only; (8) phase never gates firing.

### Spin-off triage arm (t1159_3, depends: _1)

- `monitor_shared.py`: `_CONCERN_MARKS` + `"spinoff": "»"` (single-width); `_ConcernRow` fourth mutually-exclusive state (`t` key); `ConcernPickResult` gains `spun_off: list[Concern]` **with no default** — amend every constructor and test literal in the same commit (contract-completeness); modal help texts + `_context_line()`.
- `apply_concern_pick_result`: spun_off → worker `_spawn_concern_tasks`; per concern: `aitask_create.sh --batch --silent --name <unique_name> --desc-file - --priority <c.priority> --labels shadow-concern --followup-of <task_id> --followup-kind review_finding` with description embedding `concern_marker_line(c)` (canonical `.body` — FORWARD role, register in the t1294 AST guard `tests/test_concern_body_display_contract.py`).
  - **Collision-safe naming (required):** `get_draft_filename()` timestamps at minute precision (`date '+%Y%m%d_%H%M'`), so same-name spin-offs within one minute target the same draft path and the later `ait_atomic_render` silently replaces the earlier one — made *persistent* if both were also store-marked. A batch-position index alone is NOT enough (same-minute second confirmation regenerates the same names), and a worker-start epoch **second** is not either (separate confirmations, concurrent monitor instances, or overlapping workers can share a second). Use a cross-process nonce: per-batch `uuid.uuid4().hex[:8]` + 1-based index — `shadow_<region>_<nonce>_<i>` — with suffix-preserving truncation (truncate the region segment, never the nonce/index, when applying the name-length cap). Tests: multiple same-region spin-offs in one confirmation → distinct paths; **two distinct confirmations frozen to the identical epoch second** (patched clock) → distinct paths, first batch's drafts intact.
  - **Provenance:** `--followup-of <task_id>` (the **reviewed** task from the picker context — anchors the draft to that task's topic root) + `--followup-kind review_finding` (canonical vocabulary in `lib/followup_kinds.py`, validated pre-write). Confirm at implementation that both flags flow through the draft (no `--commit`) path; if `--followup-of` resolution requires a live task lookup that fails for the draft path, record the anchor in the description and flag it.
  - Draft creation (no `--commit`): offline-safe, reversible, anti-bloat. **Report draft paths** (that is what `--silent` prints; drafts have no IDs until finalization) — notify "N concern(s) parked as drafts in `aitasks/new/` — finalize with `ait create`". No task id → visible warning, no subprocess.
- **Loop hygiene:** after successful creation, `aitask_shadow_rejected.sh add <task_id> --producer spinoff` so next round suppresses the now-tracked concern (reuses t1427's store as designed).
