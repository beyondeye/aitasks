## Summary

Adds the `aitask-screen-recording` skill and its helper. The skill turns a
screen-recording video into contact sheets, key frames, a timeline and measured
animation timing that a coding agent can read, since agents read images but not
video. It started as a personal skill, was then promoted into the framework
(aitask- prefix, helper under `.aitask-scripts/`, whitelists, ported wrappers,
tests under `tests/`), and comes with a design review of existing resources for
future expansion.

## Probable User Intent

The user needs to feed screen recordings to Claude Code for two recurring jobs:

- design-animation prototypes to implement, where exact duration and easing
  matter;
- bug reports.

Claude Code cannot read video, and the existing third-party tools sample at
≥ 1 s or by scene score, so they miss short animations and never measure
timing. The user asked first for a skill with both modes plus proper tests,
then for a design review of resources to expand it later. Finally they asked
for the skill to follow aitasks framework conventions (the `aitask-` prefix)
so it can be wrapped into the repository and grown through follow-up tasks.

## Final Implementation Notes

- **Actual work done:** as listed above. All 52 tests pass under pytest and
  unittest (about 36 s); `aitask_skill_verify.sh` reports wrapper parity clean.
  The seed-manifest, agent-config-seed, skill-verify, touchpoint-contract and
  render-wrapper tests pass, and the wrapper is shellcheck-clean with sources
  followed.
- **Deviations from plan:** N/A (retroactive wrap; no prior plan existed).
- **Issues encountered (fixed before wrapping):**
  - Max−min travel spread was inflated by an anti-aliased sliver frame near
    the end position. That pushed spring recordings onto the blend signal and
    the spring fit failed. Fixed with an 80th-percentile spread; the regression
    test fails against the old formula (mutant checked).
  - Bug mode sampled ordinary transitions; the interval now counts from the
    start of the run.
  - Contact sheets included the analysis padding.
  - Duration uncertainty was understated (±½ frame instead of ±1).
  - The synthetic fixtures redrew 450 frames pixel by pixel per test. A
    solid-fill fast path and lazy frames took the suite from 86 s to 36 s.
- **Key decisions:**
  - mpdecimate only *finds* segments. Timing is measured on every native frame
    with the tool's own thresholds, because mpdecimate defaults drop ease-out
    tails.
  - The edge signal reads progress from the leading edge of the
    change-vs-start bounding box, which keeps overshoot and handles elements
    entering from off-screen.
  - Visible duration is reported but documented as reading short for slow
    tails; the fitted duration is the value to implement.
  - Stdlib-only Python, so the helper needs no new pip dependencies. ffmpeg is
    a runtime requirement the skill reports, not an `ait setup` dependency
    (E15 in the review).
  - Outputs go to a scratch directory and are never written into the repo, and
    nothing is uploaded.
