# goengines — the framework's Go executables

One Go module (`github.com/beyondeye/aitasks/goengines`) for every Go
executable the framework distributes. Framework repository only: the release
tarball does not include it; users receive prebuilt binaries.

Specification: `aidocs/testing_engine/n014_explorer_006_proposal.md`
(*Go engine and CLI (M1.2)*, *Engine binary identity and budget (M1.2)*).

## Source of truth

Whether this tree is edited here is decided by one file, `EXPORT.txt`, in this
directory:

- **No `EXPORT.txt` — legacy mode.** `goengines/` is developed in this
  repository, and every section below applies as written. CI runs gofmt, vet,
  the hang-guard preflight, `go test`, the cross-build and the bench gate.
- **`EXPORT.txt` present — export mode.** The tree is **generated**: it is a
  snapshot of the private `aitasks_go` repository's reviewed `export` branch,
  copied with its import paths rewritten. **Do not edit it here** (see
  *Emergency fixes* for the one exception). Development, tests, testdata,
  benches and `ci/` live in aitasks_go. Its private gate ran them at the
  exported commit and recorded the results in `EXPORT.txt`. Every exported
  `.go` file opens with
  `// Code generated by aitasks_go export from <sha>; DO NOT EDIT.`. The
  export commit carries the trailer `Exported-From: beyondeye/aitasks_go@<sha>`,
  plus `Migrated-From: beyondeye/aitasks@<sha>` on the bootstrap export and
  `Drift-Returned-In: <private sha>` when it absorbs a returned fix.

The bootstrap export (the testmap cutover) creates `EXPORT.txt`, so the commit
that changes the source of truth also switches CI. There is never a window in
which neither mode's validation runs.

**Public-maintained files:** only `README.md` and `.gitignore`. An export
never writes them. Every other path is either part of the export or refused
by the exporter.

### `EXPORT.txt` (format 1)

The record is line-oriented. Each line is blank, a `#` comment, or a
`key: value` pair, and paths are relative to `goengines/`:

```
format: 1
source: beyondeye/aitasks_go@<40 or 64 hex sha>
manifest: sha256:<hex>                     # the export manifest's digest
migrated-from: beyondeye/aitasks@<sha>     # bootstrap export only
gate: <name> <result>                      # one per private gate step
file: <64 hex sha256> <path>               # one per exported file, sorted
removed: <path>                            # paths a previous export owned
```

- `format: 1` and `source:` must each appear exactly once.
- A `file:` path uses `[A-Za-z0-9._/@+-]` only. It is relative and canonical
  (no empty, `.` or `..` segment), it is listed once, and it never names
  `EXPORT.txt`, `README.md` or `.gitignore`.
- Unknown keys are ignored; `format:` is the version gate.

### CI in export mode

`.github/scripts/goengines_integrity.sh` replaces the suite. It lives outside
this tree, because nothing here is public-maintained except the two files
above. It has three verbs:

- `mode` prints the mode.
- `check` is the required check. It validates the record, gofmt, and that no
  `github.com/beyondeye/aitasks_go` module appears in `go.mod`, `go.sum`, the
  module graph or any package's imports. It runs an independent build with no
  private access (`go mod tidy -diff`, `go build ./...` on every release
  target, `go vet`). It also confirms that `cmd/ait-testmap`'s dependency
  closure, and `cmd/ait-monitord`'s when present, stays inside the allowlist
  below with no `tui/` package.
- `drift` compares the tree with the record's hashes. It reports a modified,
  missing or unlisted file as a **warning** and never fails.

The platform-dependent checks run once per `build.sh` release target, because
`go list` only sees one platform's files. The release job runs `check` before
`build.sh all`. `ait engine test` runs `check` and `drift` in place of the
suite.

### Emergency fixes

A fix that cannot wait for the next export may be committed here directly:

1. Commit it under an aitasks task, with the trailer `Return-To: aitasks_go`.
2. In the same session, create a return task in aitasks_go that names the
   public commit:
   `ait create --batch --project aitasks_go --name return_<topic> --desc "Port aitasks <commit> back: …"`.
3. CI reports the changed files as drift, as a warning. It never blocks a
   release: emergency fixes must ship.
4. The return task pulls the fix back into aitasks_go
   (`promote/export.sh --pull-back`). Until it lands, the next export refuses
   to overwrite the public fix. The export that absorbs it passes
   `--drift-returned-in <private sha>`.

## Development

Since the aitasks_go#t22 cutover, this tree is developed in the private
`beyondeye/aitasks_go` repository, in its nested `goengines/` module. Its
`goengines/README.md` documents:

- the layout of the development tree;
- the build, test and bench commands, including dash parity;
- the bench gate's host normalization;
- the rules for engine submodules.

Here only `build.sh` and the integrity checks described above apply.

### Evidence contract (M3.2)

The guarantees every runner result rests on (`runner/describe.go`,
`reconcile.go`, `results.go`, `invoke.go`; M3.2a). Each M3.2 adapter
consumes them; none may weaken them.

| # | guarantee |
|---|---|
| G1 | **Command outcome ≠ accounting.** Every top-level result carries its runner's `accounting:` class: `cases` (the engine reconciled the unit's expected case identities from discovery, identity by identity, against the adapter's case results of this invocation), `unit` (one executable whose exit is its verdict; the default), `aggregate` (one command over many tests; proves the command's exit only). A run prints both `RUN_RESULT` and `RUN_ACCOUNTING` |
| G1a | **Identity-based, engine-owned reconciliation.** Each expected identity needs exactly one terminal result; a missing, duplicate, unexpected or malformed one makes the unit `error:incomplete\|duplicate_case\|unexpected_case\|malformed_case`, whatever the totals. Counters are computed by the engine; an adapter never writes a `cases` unit's top-level result |
| G1b | **Unit status from validated cases:** any `fail` → `fail`; else any `error` → `error`; else zero expected → G3; else every case `skip` → `skip`; else `pass` (skipped cases counted and listed). A reconciliation error is `error` first |
| G2 | **Never a pass, never an unexplained skip** from missing, ambiguous, stale or incomplete evidence: the unit is `error` with a stated reason, or the invocation a mechanism failure |
| G3 | **Zero tests is a policy:** a `cases` unit that expected zero cases is `error`, or `skip` under `zero_tests: skip`, with reason `zero_tests` printed and in the ledger; never a pass. Rejected evidence outranks it; after an engine kill it never applies |
| G4 | **`skip` only from the tool's own per-case verdicts or from G3.** An adapter never synthesizes one |
| G5 | **Discovery is declared:** `native` (the framework's collector under the execution configuration, bounded like execution), `inventory` (an explicit enumerable rule or list), `candidates` (a source scan; `run`, `scan` and `check` print `DISCOVERY:<runner>\|candidates`) |
| G6 | **Freshness:** reports are read only from the per-invocation report directory, created empty; older, linked or outside files are refused as stale |
| G7 | **Child rows only through a registered reporting contract,** through the same reconciler; a discovered subsumed unit with no evidence counts as `unaccounted` |
| G8 / G8a | **Supervision with containment** (t1854_6): every process an adapter or runner starts runs bounded and cancellable under a per-start supervisor whose subtree a descendant cannot leave by changing its process group or session, cleaned up and proven empty (ECHILD). Per-invocation cleanup ownership survives the death of every process that runs test code; **the supervisor's own death is a stated residual** (detected, recorded, halts all further work). Without a supervisor (darwin) production adapters refuse (`CONTAINMENT_UNAVAILABLE`). cgroup v2 hardening is a deferred follow-up. Every containment backend in `procsup.Backends()` must keep G9's cleared-environment detection (`TestRecursionBackendsCovered`) |
| G9 | **Runtime recursion refusal** for the same repository, in `run` and `Load`, through the context, the `AIT_TESTMAP_ACTIVE` marker and the holder-record ancestry backstop (Interfaces: *recursion guard*) |
| G10 | **Support claims:** an adapter is supported only for the tool versions and platforms its real-tool integration tests run against (`AIT_TESTMAP_REQUIRE_REAL_TOOLS=1` in CI); without one it stays pending |

What each status proves:

| status | proves | does not prove |
|---|---|---|
| `pass` | it ran in this invocation, under its bound. `cases`: every expected identity has exactly one terminal result, none failed or errored, at least one passed. `unit`: the executable exited 0. `aggregate`: the command exited 0 | that the assertions are meaningful; that skipped cases ran; anything about cases discovery did not find (`candidates`); which tests ran inside an `aggregate` |
| `fail` | at least one case failed, or the executable / command exited non-zero | where the fault is |
| `error` | the unit could not be judged: a case error with no failure, collection or build failure, incomplete / duplicate / unexpected / malformed / stale evidence, `zero_tests`, a protocol violation | anything about the code under test |
| `skip` | every expected case was skipped by the tool (with reasons), or G3 applied | any behaviour |
| `timeout` / `not_started` / `batch_timeout` / `missing` / `refused` | as in the timeout model and the outcome table above | — |
